A front‑end, UI/UX, accessibility and branding audit of the current build — and the design system required to turn it from a working analysis script into a reference‑grade operational handbook a consultant can put their name on.

00 · Executive summary

The one-sentence finding

The analytical product is already differentiated and defensible. The interface is not — it is the framework's default, and it currently contradicts the product's core promise in three places a client will see first.

What is working

  • The information is right. Relabel reconciliation, threshold-based mover detection, coverage and a dedicated needs_review section are all surfaced on one page. Most tools in this category surface none of them.
  • The epistemic discipline is stated in the UI, not just in the code: "Where the notes are silent, the tool says so instead of inventing a reason."
  • The headline structure is correct — old footprint, new footprint, delta, coverage, movers — and it appears above the fold.
  • Input handling is honest. "Any column names are fine… You confirm which is which below. Nothing is assumed silently." That sentence is the product's thesis and it is already written.

What is undermining it

  • A favourable result is painted red. The −1.68% delta renders in #BD4043 on a red wash, three centimetres from a green panel saying the footprint did not increase. The two signals disagree.
  • The primary action is a red button (#FF4B4B, framework default) at 3.30:1 contrast. On a carbon tool, "Run analysis" is styled as a destructive action and fails WCAG 1.4.3.
  • The discipline that justifies the price is the least legible text on the page. Every caption is set at opacity:.6 → 3.69:1, failing AA. That includes the "we do not invent reasons" sentence.
  • Tables are painted to <canvas>. They cannot be read by assistive tech, selected, searched by the browser, or printed. For an audit tool, that is a category error.
  • The deliverable is a Markdown button. The consultant's actual job — producing a defensible client pack — ends at the least prominent control on the page.

01 · User flow & architecture

The app models a calculation. The consultant runs a case.

Everything the interface knows about is one anonymous, unnamed, unrepeatable calculation. Everything the user is accountable for is a named client, a dated deliverable, a review trail and a comparison against what they signed last year. That gap is the root cause of most friction below.

Current journey, as built

01Set labels

Two free-text fields, "2025" and "2026". Nothing binds them to the workbooks actually loaded.

02Upload inventory

CSV/XLSX, 200 MB cap. Unlabelled input (A‑07).

03Confirm columns

Promised in the copy — "You confirm which is which below" — but not visible in the default state. The promise arrives before the affordance.

04Run analysis

One button at the foot of a scrolling sidebar. Disappears entirely below 768 px (A‑09).

05Read one long page

KPIs → relabels → contributors → explanations → needs‑review → export. No navigation, no anchors, no return path.

06Download Markdown

Terminal step, lowest visual weight on the page, single format, no provenance stamp.

Six structural gaps

F‑01There is no run identity

A consultant who re‑bases twelve clients produces twelve runs a year and must be able to say, in twelve months, exactly which workbook version, which mapping and which overrides produced a given figure. The app has no run ID, no timestamp, no client name and no persistence. Every session is unattributable.

FixIntroduce a first-class Run object: client · product · old-version · new-version · mapping-hash · factor-set checksum · operator · UTC timestamp · run-id. Stamp it into the page header, every export and every copied figure. This single object unlocks history, comparison, sign-off and reproducibility — it is the highest-leverage change in this report.
F‑02Configuration and action share one collapsing rail

The sidebar holds version labels, upload, method configuration and the only submit control. It scrolls, so the CTA sits below the fold; it auto-collapses under the framework's breakpoint, so on a tablet the application presents as a read‑only report with no way to change anything.

FixSeparate setup from commit. Keep parameters in the rail; move the primary action to a persistent action bar pinned to the result canvas that also carries run state (Ready · Running · Complete · Stale). Below 768 px the rail becomes a full-screen sheet reached from that bar, so the action is never the thing that disappears.
F‑03Staleness is invisible

Reactive frameworks re‑execute on input change without announcing it. A user who edits a version label after reading results cannot tell whether the numbers on screen correspond to the inputs on screen. In a tool whose entire value is traceability, an ambiguous "is this current?" state is disqualifying.

FixExplicit state machine on the run header — idle → queued → running → complete → stale. On stale, dim result surfaces to 60% with a visible banner and a Re‑run control, and disable export. Never silently recompute a figure a user may already have copied.
F‑04The trust gate is placed after the answer

"Needs review (never guessed)" — the section that determines whether the headline number is defensible — is the second‑to‑last thing on the page, below the AI explanations. Coverage of 85.7% is reported as a bare KPI: the 14.3% that did not match is a number with no door behind it.

FixPromote reconciliation ahead of interpretation. Order: Result → Confidence → Movers → Explanations → Export. Make the coverage tile a control: clicking 85.7% opens the unmatched lines. Make the review count a queue with an explicit resolved/total counter, and let export state depend on it.
F‑05No year-over-year memory

The product's premise is an annual ritual. The interface has no concept of "last year", so the mapping work, the accepted relabels and the reviewer's judgement calls are re-done from zero every cycle — which is precisely the week of Excel archaeology the product exists to eliminate.

FixPersist mapping and review decisions per client. On the next run, pre-fill and mark each carried-forward decision as inherited from Run #…, requiring re-confirmation only where the underlying factor changed. Target: second-year runs need confirmation on the delta only.
F‑06A single scroll with no addressable positions

Six major regions on one document with no navigation and no anchors. A consultant cannot send a colleague "look at the electricity mover" — there is no URL for it. All disclosure widgets are closed by default, so the page's information scent is uniformly flat.

FixSticky section rail (Result · Confidence · Movers · Explanations · Review · Export) with scroll-spy and a per-finding deep link (/run/8f2c/mover/electricity-generated-uk). Open the top three movers by default; leave the long tail collapsed.

02 · Interface, hierarchy & accessibility

Four numbers at 36 px, and none of them is the answer

The KPI row gives equal typographic weight to the old footprint, the new footprint, coverage and mover count. Three of those are diagnostics. One of them — the change — is the thing the user came for, and it is rendered as a small red chip beneath a secondary figure.

Visual hierarchy

Current weighting

  • stMetricValue = 36 px for all four tiles
  • Delta chip = 14 px, red, subordinate
  • H1 page title consumes the largest type on screen and carries no information after the first read
  • Three green panels compete with the KPI row for attention
  • The eleven relabel families — a genuine differentiator — are one collapsed grey strip

Proposed three-tier density model

Tier 1 — Verdict (one object)
A single result card: new footprint at display size, the change as the second-largest element with an explicit word ("down 1.68% · 0.04 kg lighter"), and a confidence line — "85.7% of inventory matched · 1 line needs review" — that is a link, not a decoration.
Tier 2 — Ledger (scannable)
Movers as a real table: 13 px, tabular figures, right-aligned numerics, one row per line item, sorted by absolute impact, with a confidence badge per row. Density is a feature here — do not pad it.
Tier 3 — Evidence (on demand)
A drawer per row: the two factor values, the arithmetic, the DEFRA citation verbatim or the explicit "not explained in the notes" state, the match method and score, and a Copy with provenance action.

Screen-reader contract

The result region must be an aria-live="polite" landmark that announces one sentence on completion: "Analysis complete. Footprint 2.3 kilograms, down 1.68 percent. 85.7 percent coverage. 1 line needs review." Never announce the whole table. Announce staleness the same way.

This audience prints. The output goes into a client file, a board pack, or an assurance folder. 04 · Branding & design system

Hue should encode confidence, not direction

Defect A‑01 is not a bug in a stylesheet. It is what happens when a finance dashboard's colour convention — down is red, up is green — is applied to carbon, where down is the goal. The fix is not to swap the two colours. It is to stop using hue for direction at all.

The rule

Direction is encoded by glyph, sign and word. Hue is reserved exclusively for epistemic status: how much you can trust the number. A footprint that rises is not "bad" — it may be the correct, well-cited answer. A footprint that falls on a low-confidence match is the genuinely alarming case, and today it is painted the calmest colour on the page.

Cited

Verdigris. The change is explained verbatim in the DEFRA notes and the citation is one click away. This is the resting state and should dominate a healthy run.

Not explained

Graphite. The factor moved; the notes are silent. Deliberately neutral, deliberately unalarming — this is honest, not a failure — but never invisible.

Needs review

Ochre. The only loud colour in the system, spent on the one thing a human must decide. Its scarcity is what gives it force.

Why not green

Generic eco-green on white is the visual grammar of sustainability marketing, and this audience has learned to distrust it. They are not buying optimism; they are buying something they can defend in a room where someone is trying to poke holes in it. The palette below borrows from the objects that already carry that authority: ledgers, assurance reports, laboratory notebooks.

  • Deep verdigris — sustainability adjacency without the lime. Reads institutional. Hits 8.42:1 on white, so it works as a primary action colour without a contrast compromise.
  • Warm paper, not clinical white — signals document rather than dashboard. It is the difference between a screen you monitor and a page you sign.
  • Ochre, not red — red is spent currency in this domain and carries "error". The review flag is not an error; it is the tool working correctly.
  • Graphite as a real semantic value — "we do not know" needs its own colour, or it collapses into either reassurance or alarm. Neither is true.

05 · High-utility handbook strategy

Twelve patterns that make software feel like a reference

A tool answers a question and is closed. A handbook is opened because it is the place where the answer lives. The difference is almost entirely interface: whether every number carries its origin, whether uncertainty has a first-class home, and whether the artefact you hand a client comes out of the product rather than out of a copy-paste.

A. Provenance

P1 · Every figure carries a stamp

No number appears anywhere — screen, drawer, export, clipboard — without its chain: source workbook and sheet, row reference, DEFRA factor ID, vintage, match method, match score, run ID, UTC timestamp. Hover reveals it; Copy with provenance carries it into whatever the consultant pastes into.

0.13096 kg CO₂e/kWh
DEFRA 2026 · Electricity generated · UK · Scope 2
Sheet "UK electricity" row 14 · exact match (100)
Run 8f2c41 · 2026-07-31T09:14Z

P2 · Citation-first explanations

The DEFRA sentence appears above the generated prose, quoted verbatim with its source location, visually distinguished as evidence rather than commentary. The AI layer is explicitly framed as a reading aid, not the authority. When the notes are silent, that state gets its own designed treatment — a neutral panel reading "Not explained in the DEFRA notes" with the raw before/after values — rather than an absence or an apology.

P3 · The method note is a destination

Thresholds, matching algorithm, confidence cut-off and their version history live at a stable URL, written once. Every threshold mentioned anywhere in the UI links to its definition. When a client asks "what counts as a mover?", the consultant sends a link rather than an explanation.

P4 · Definitions in place

Dotted-underline popovers on relabel family, mover, coverage, Scope 2, flat baseline. One sentence plus a link. Junior analysts learn the domain from the tool; senior ones stop being asked.

B. Uncertainty as a feature

P5 · The review queue is a gate

Unmatched and below-threshold lines get a dedicated, keyboard-first queue with a visible n of m resolved counter. Export is not blocked, but exporting with unresolved items requires an explicit acknowledgement that is recorded in the export itself. The consultant can always ship; they can never ship silently.

P6 · Coverage opens

85.7% becomes a control. Clicking it lists the 14.3% — every unmatched line, its best candidate, its score, and why the score fell short. A coverage figure with no door behind it is a number the consultant cannot defend.

P7 · Confidence is visible in the ledger

Every mover row shows its match method and score inline, not only in a drawer. The reader should be able to scan the ledger and see, without a click, which rows rest on an exact match and which rest on a judgement.

P8 · Empty and edge states instruct

"No movers crossed the threshold" is a finding, not a blank region — say so, state the threshold, and offer to lower it. Zero-coverage uploads explain which columns were expected. Every dead end names the next action.

C. The artefact

P9 · A client-ready export pack

Markdown alone serves the developer, not the consultant. Ship four artefacts from one action: XLSX (movers, full mapping, review log, method sheet), PDF memo (verdict, top movers, citations, sign-off block), Markdown (for internal notes), JSON (for the client's own systems). All four carry the same run ID, so any figure in any of them can be traced to the same source.

P10 · Pre-export checklist

A short, honest gate before download: review queue resolved · column mapping confirmed · relabel families accepted · unexplained movers acknowledged · client and vintage named. Unchecked items are listed in the export's front matter. This is the interface expression of the product's whole thesis.

P11 · Sign-off ledger

Who ran it, who reviewed it, what was overridden and why — appended, never edited. Twelve months later this is the difference between "I believe that was a rename" and "here is the record". It costs one table and it is the reason a firm standardises on the tool.

P12 · Reproducibility on one control

Re-run this exact configuration — same mapping, same overrides, new factor set. A permalink restores the full run. The annual ritual becomes: open last year's run, press re-run, adjudicate only what changed. That is the ten-minute task the vision describes, and it is reachable from where the product already stands.

The design principle underneath all twelve

The interface must never be more confident than the computation. The engine already refuses to guess. Right now the interface guesses on its behalf — by painting a favourable number in an alarm colour, by hiding the no-guess statement at 3.69:1, by placing the review queue after the conclusion, and by shipping a Markdown file with no run identity. Align the interface's confidence with the engine's, and the product's differentiator becomes something a client can see rather than something the consultant has to explain.

Validation checklist

Accessibility

  • All text ≥4.5:1; UI boundaries ≥3:1
  • Full keyboard path: upload → run → review → export
  • Visible focus on every control, never suppressed
  • Tables expose row/column semantics to AT
  • Greyscale render still distinguishes all states
  • Targets ≥44×44 px

Responsiveness

  • 375 / 768 / 1024 / 1280 / 1440 all pass
  • No horizontal scroll below 640 px
  • Controls reachable at every width
  • Print produces a complete, expanded document
  • 200% zoom without loss of function

Product integrity

  • No figure renders without provenance
  • Stale state always visible
  • Unresolved review items recorded in exports
  • Every threshold links to its definition
  • Any run reproducible from its permalink

Risks & uncertainties

  • [NEEDS VERIFICATION] Desktop rendering at ≥1280 px was not observable; A‑06 and A‑09 may present differently or resolve entirely at that width.
  • [NEEDS VERIFICATION] Keyboard tab order, focus-visible styling and screen-reader output were inferred from DOM structure, not from assistive-technology testing. Commission a manual NVDA/VoiceOver pass before any accessibility claim is made externally.
  • [NEEDS VERIFICATION] Replacing the framework's canvas data grid may require leaving its native dataframe component. Feasibility inside the current stack is unconfirmed.
  • [UNCERTAIN] The relabel-pairing and threshold logic were read from the interface's own summary text, not from source. All statements here concern presentation only and make no claim about analytical correctness.
  • [NEEDS VERIFICATION] Suppressing hosting-platform chrome may depend on the deployment tier. Confirm before promising an owned shell for client-facing use.
  • Non-technical risk: the accessibility defects above are the kind that surface in enterprise procurement questionnaires. Closing the P0 set is cheap now and expensive under a VPAT request later.

Closing

The engine already refuses to guess. Every recommendation in this document exists to make the interface keep the same promise — so that the discipline a consultant is paying for is the first thing their client sees, not the last thing they have to explain.
